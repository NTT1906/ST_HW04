# BUG-004 — Lack of Referential Integrity on Category Deletion (Orphaned Products)

**Bug ID:** BUG-FR14-004  
**Feature:** FR-14 — Category Management (CRUD)  
**Date Reported:** 2026-07-07  
**Reported By:** AI (Antigravity) via EXEC-01  
**Linked Test Cases:** TC-DT-008  
**Severity:** High  

---

## Title

Deleting a category associated with active products succeeds, leaving orphaned product references in the database.

---

## Environment

| Item | Value |
|------|-------|
| Frontend | http://localhost:5174 (Admin React/Vite) |
| Backend | http://localhost:3000 (Node.js/Express + SQLite) |
| Browser | Chromium (Playwright headless) |
| OS | Windows |
| Admin | `admin@eshop.com` / `Admin123!` |

---

## Preconditions

1. Admin is authenticated and on Category page.
2. Category `#1 Điện thoại` exists and is linked to products (e.g. `iPhone 15 Pro Max` and `Samsung Galaxy S24 Ultra` have `category_id = 1`).

---

## Steps to Reproduce

1. Click the "Xóa" button in the row for category `Điện thoại`.
2. Observe the Category list.
3. Navigate to the Products page and inspect the products originally assigned to that category.

---

## Expected Result

- Deletion is blocked or prompts a warning (e.g. "Không thể xóa danh mục này vì vẫn có sản phẩm liên kết").
- Product database table maintains referential integrity (either deletion blocked, or cascade nullified, or reassigned).

---

## Actual Result

- The category is deleted successfully.
- Table refreshes and the row for `Điện thoại` is removed.
- Switching to the Products tab shows that the products (e.g., iPhone 15, Samsung S24) remain in the system, but their category fields are orphaned (referencing the non-existent category ID 1). The admin products UI continues to load them without crashing.

## Severity Assessment

**High**

- **Functional impact:** While the admin panel loads the products list without crashing, the customer storefront and other filtering services may break when executing database joins on non-existent category records, or products may disappear from storefront category filters. This violates referential integrity principles.
- **Security:** No security impact.
- **Workaround:** None.

## GitHub Issue Draft

```markdown
## [BUG] FR-14: Deleting category orphans associated products

**Severity:** High  
**Feature:** FR-14 — Category Management  
**Endpoint:** DELETE /api/categories/:id  

### Description
The category deletion endpoint does not check for active product references before removing categories from the database. Consequently, deleting a category removes the category row, leaving related products in an inconsistent state where their `category_id` references a non-existent category record.

### Steps to Reproduce
1. Ensure category "Điện thoại" (ID: 1) contains active products.
2. Log in as admin and go to the "Danh mục" tab.
3. Click "Xóa" on "Điện thoại".
4. The category is deleted.
5. Go to the "Sản phẩm" tab — note the products are still present.

### Expected Behaviour
Category deletion is blocked or returns an error alert while products remain linked.

### Actual Behaviour
Category is deleted instantly, leaving orphaned product rows in database.
```
