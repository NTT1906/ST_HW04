# BUG-001 — Broken Access Control (Privilege Escalation) on Category Modification Routes

**Bug ID:** BUG-FR14-001  
**Feature:** FR-14 — Category Management (CRUD)  
**Date Reported:** 2026-07-07  
**Reported By:** AI (Antigravity) via EXEC-01  
**Linked Test Cases:** TC-DT-011  
**Severity:** Critical  

---

## Title

Category creation (`POST /api/categories`) and deletion (`DELETE /api/categories/:id`) routes do not enforce admin role checks, allowing regular users to execute them.

---

## Environment

| Item | Value |
|------|-------|
| Frontend | http://localhost:5174 (Admin React/Vite) |
| Backend | http://localhost:3000 (Node.js/Express + SQLite) |
| Browser | Chromium (Playwright headless) |
| OS | Windows |
| Regular User | `test@eshop.com` / `Test1234!` |
| Admin | `admin@eshop.com` / `Admin123!` |

---

## Preconditions

1. User `test@eshop.com` is registered and has standard customer privileges (`role === "user"`).
2. Backend API is active at `http://localhost:3000`.
3. Admin panel is active at `http://localhost:5174`.

---

## Steps to Reproduce

1. Log in as a regular user via the API endpoint `POST /api/login` using the email `test@eshop.com` and password `Test1234!`.
2. Extract the returned authentication token (`JWT`).
3. Make a direct HTTP request to create a new category using the regular user's token:
   ```http
   POST /api/categories
   Authorization: Bearer <user_jwt_token>
   Content-Type: application/json

   { "name": "UserBlocked" }
   ```
4. Observe the response code and category creation result.
5. Make a direct HTTP request to delete an existing category (e.g. ID `2`) using the regular user's token:
   ```http
   DELETE /api/categories/2
   Authorization: Bearer <user_jwt_token>
   ```
6. Observe the deletion response.

---

## Expected Result

- The API should reject both requests with HTTP `403 Forbidden` or `401 Unauthorized`.
- Standard user tokens must be blocked from adding or removing categories.

---

## Actual Result

- Both requests succeeded with status `200 OK`.
- The new category `"UserBlocked"` was successfully inserted.
- The existing category `#2` ("Laptop") was successfully deleted.

**API response logs:**
- Create: `POST /api/categories` → `200 OK` with body `{"message": "Category created", "id": 11}`
- Delete: `DELETE /api/categories/2` → `200 OK` with body `{"message": "Category deleted"}`

---

## Severity Assessment

**Critical**

- **Functional impact:** Any standard user can alter the store configuration, disrupting product categorization, creating clutter, and deleting important categories.
- **Security:** Severe privilege escalation vulnerability. The authentication middleware verifies the token signature but fails to check role attributes.

```markdown
## [BUG] FR-14: Broken Access Control allows regular users to create and delete categories

**Severity:** Critical  
**Feature:** FR-14 — Category Management  
**Endpoints:** 
- POST /api/categories
- DELETE /api/categories/:id

### Description
The category mutation endpoints (`POST /api/categories` and `DELETE /api/categories/:id`) only use the generic `authenticateToken` middleware which verifies token validity, but fail to verify if the authenticated user has the "admin" role. As a result, standard customer accounts can create and delete product categories directly.

### Steps to Reproduce
1. Retrieve JWT token for test@eshop.com (role: user) via POST /api/login.
2. Submit a POST request to `/api/categories` with body `{"name":"MaliciousCategory"}` using the user token.
3. Observe status 200 OK and category created.
4. Submit a DELETE request to `/api/categories/1` using the user token.
5. Observe status 200 OK and category deleted.

### Expected Behaviour
API returns 403 Forbidden for non-admin accounts.

### Actual Behaviour
API returns 200 OK and executes the changes.

### Environment
- Backend: http://localhost:3000
- Test user: test@eshop.com (non-admin)
```
