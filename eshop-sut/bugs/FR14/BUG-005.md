# BUG-005 — API Response Inconsistency (Deleting Non-existent ID Returns Success)

**Bug ID:** BUG-FR14-005  
**Feature:** FR-14 — Category Management (CRUD)  
**Date Reported:** 2026-07-07  
**Reported By:** AI (Antigravity) via EXEC-01  
**Linked Test Cases:** TC-DT-009  
**Severity:** Low  

---

## Title

Sending a `DELETE` request for a non-existent category ID returns status `200 OK` and a success message.

---

## Environment

| Item | Value |
|------|-------|
| Frontend | http://localhost:5174 (Admin React/Vite) |
| Backend | http://localhost:3000 (Node.js/Express + SQLite) |
| Browser | Chromium (Playwright headless) |
| OS | Windows |
| Admin | `admin@eshop.com` / `Admin123!` |

---

## Preconditions

1. Admin authentication token is active.
2. The category ID `99999` does not exist in the database.

---

## Steps to Reproduce

1. Issue a direct HTTP request to the backend:
   ```http
   DELETE /api/categories/99999
   Authorization: Bearer <admin_jwt_token>
   ```
2. Observe the HTTP status code and response payload.

---

## Expected Result

- API returns `404 Not Found` or `400 Bad Request` indicating that the target resource was not found or no rows were deleted.

---

## Actual Result

- API returns `200 OK` with response body `{"message":"Category deleted"}`.

---

## Severity Assessment

**Low (Cosmetic / Developer UX)**

- **Functional impact:** The API misleads client systems into thinking a deletion occurred when the target resource was never present. While it does not corrupt any existing data, it represents poor API design and can cause client synchronization state errors.
- **Workaround:** None.
