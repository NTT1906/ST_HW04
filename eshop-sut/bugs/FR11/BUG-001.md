# BUG-001 — Order History API Returns All Orders Without Enforcing Pagination Limit

**Bug ID:** BUG-FR11-001  
**Feature:** FR-11 — Order History View (User)  
**Date Reported:** 2026-07-07  
**Reported By:** AI (Antigravity) via EXEC-01  
**Linked Test Cases:** TC-DT-011, TC-BVA-006  
**Severity:** Medium

---

## Title

`GET /api/orders/my-orders` does not enforce the stated maximum 10-order pagination limit — all orders are returned and displayed.

---

## Environment

| Item | Value |
|------|-------|
| Frontend | http://localhost:5173 (React/Vite) |
| Backend | http://localhost:3000 (Node.js/Express + SQLite) |
| Browser | Chromium (Playwright headless) |
| OS | Windows |
| Test User | `test@eshop.com` |

---

## Preconditions

1. User `test@eshop.com` is authenticated (valid JWT).
2. The user has **more than 10 orders** associated with their account in the database.  
   *(During testing: 19 orders were present for `user_id=2`.)*
3. Backend service is running at `http://localhost:3000`.
4. Frontend is running at `http://localhost:5173`.

---

## Steps to Reproduce

1. Log in as `test@eshop.com` / `Test1234!`.
2. Using the admin API or by placing multiple orders, ensure the user has **more than 10 orders** in the system.
3. Navigate to `http://localhost:5173/profile`.
4. Observe the **Lịch sử đơn hàng** (Order History) table.
5. Also call the API directly:
   ```
   GET http://localhost:3000/api/orders/my-orders
   Authorization: Bearer <user_token>
   ```

---

## Expected Result

- The API (`GET /api/orders/my-orders`) returns a **maximum of 10 orders** per call.
- The UI renders **at most 10 rows** in the order history table.
- Orders beyond the first 10 are not shown (with or without a pagination indicator).

> **Source of expectation:** Reviewer-confirmed specification via OQ-04: *"Yes, 10 max"* — captured in `DT-01-feature-understanding.md` §8.

---

## Actual Result

- The API returned **all 19 orders** for the user — no limit enforced.
- The UI rendered **all 19 rows** in the order history table.
- There is no visible pagination control, "load more" button, or truncation indicator.

**API response excerpt:**
```
GET /api/orders/my-orders  →  HTTP 200
Body: [...array of 19 order objects...]
```

## Severity Assessment

**Medium**

- **Functional impact:** Users with many orders see a potentially very long, unmanageable list without pagination controls. This degrades the user experience and may cause performance issues.
- **Data integrity:** No data is corrupted — this is a display/API limitation issue.
- **Security:** No security impact.
- **Workaround:** None available to the user.
